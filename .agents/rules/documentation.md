# Documentação

- Mudanças estruturais ou decisões relevantes devem ser registradas em `docs/refactoring`.
- Documentação deve indicar:
  - objetivo;
  - problema;
  - decisão;
  - arquivos envolvidos;
  - testes;
  - pendências;
  - riscos.
- Não documente uma funcionalidade como concluída se ainda depender de homologação externa.
